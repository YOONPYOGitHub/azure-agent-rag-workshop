## 시나리오
한빛테크 직원이 도쿄 출장 계획을 세웁니다. 규정에서 숙박 한도와 승인 절차를 찾고, 참고 환율로 금액을 환산하며 현재 날씨를 조회합니다. 챗봇이 실제 예약·결제·승인을 하지는 않습니다.

## 반드시 전달할 구분
1. LLM 답변 ≠ 검증된 실시간 사실
2. function_call 요청 ≠ 함수 실행
3. 인덱싱 ≠ 모델 파인튜닝
4. 검색 결과 ≠ 모두 관련 있는 정답 근거
5. 문서에 없는 규정 ≠ 추측으로 채울 내용
6. 학생 환경 변수 ≠ 서버 권한 경계
7. 로컬 Agent ≠ Foundry에 호스팅된 Agent Service

## 선택 확장: 심플한 2단계 협업
기본 과정 완료 후 `작성 에이전트 → 검토 에이전트`로 나눌 수 있습니다. 검토자는 새 정보를 만들어내지 않고 **이미 검색한 근거와 작성 답변**만 받아 인용·누락·불확실성을 지적하도록 합니다. 이는 추가 아이디어이며 기본 앱은 멀티 에이전트가 아닙니다. 모델 호출 수/비용/지연이 늘어나므로 단일 에이전트 대비 개선을 측정한 뒤 채택합니다.
