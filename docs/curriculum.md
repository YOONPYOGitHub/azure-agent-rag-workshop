# 6시간 워크숍 · AI 이해부터 Agent + RAG 앱까지

**대상:** AI/Python 초보자 10명. 문법 암기나 클라우드 구축보다 “어디서 정보를 얻고 누가 실행했는가”를 설명하는 것이 우선입니다.
**시나리오:** 가상 회사 한빛테크 직원의 도쿄 출장. 숙박 한도/승인 절차를 문서에서 찾고, 참고 환율로 환산하고, 현재 날씨를 조회합니다. 실제 예약·결제·승인은 하지 않습니다.
**최종 산출물:** Codespaces(우선) 또는 로컬에서 실행되는 Streamlit 앱, 세 학습 모드 비교표, 직접 추가한 평가 사례 하나.

## 정확히 360분: 수업 330분 + 휴식 30분

경과 시간 기준입니다. 예를 들어 시작이 오후라도 아래 `00:00`은 수업 시작을 뜻합니다. 점심은 포함하지 않으며 별도 점심을 넣으면 전체 체류 시간이 늘어납니다.

| 경과 시간 | 분 | 구간 | 진행 / 통과 증거 |
|---|---:|---|---|
| 00:00–00:35 | 35 | 00 환경과 AI의 한계 | 역할 구분 10 + 준비/첫 호출 15 + 지침 변경/기록 10 |
| 00:35–01:20 | 45 | 01 LLM과 함수 실행 | 설명/단독 함수 10 + 수동 루프 15 + auto/none 실험 15 + 체크 5 |
| 01:20–01:30 | 10 | 휴식 1 | 요청 중단, 강사 개별 연결 지원 |
| 01:30–02:05 | 35 | 02 Agent loop | 설명 10 + Framework/세션 실험 20 + 체크 5 |
| 02:05–02:55 | 50 | 03 문서·청크·인덱싱 | 원문/청킹 15 + 임베딩 관찰 10 + 개인 업로드/읽기 확인 20 + 체크 5 |
| 02:55–03:05 | 10 | 휴식 2 | 인덱스 문제 개별 지원 |
| 03:05–04:00 | 55 | 04 검색과 RAG | 세 검색 방식 20 + 문서 전달/미전달 실험 20 + 인용 검토 10 + 체크 5 |
| 04:00–05:05 | 65 | 05 Agent와 최종 앱 | 도구/세션 실험 15 + 앱 실행 10 + 모드 비교 25 + 짝 시연/수정 15 |
| 05:05–05:15 | 10 | 휴식 3 | 화면/키 비노출 점검 |
| 05:15–06:00 | 45 | 06 평가와 마무리 | 평가 기준 10 + 실행/한 사례 추가 15 + 결과 공유 10 + 안전/종료 10 |

필수 구간 합계: `35 + 45 + 35 + 50 + 55 + 65 + 45 = 330분`.
휴식 합계: `10 + 10 + 10 = 30분`. 전체: `330 + 30 = 360분 = 6시간`.

## 진행 방식: 예측 → 실행 → 관찰 → 변경

매 노트북에서 **실행 전 예측**, 실제 출력 관찰, **변수 하나만 변경**, 전/후 기록을 반복합니다.
기본 셀은 완성된 최소 예제로 실행 가능합니다. 수강생은 질문·지침·설정값·평가 사례를 바꾸며 배웁니다.
참고 풀이는 접힌 `<details>` 안에 있고 Run All로 실행되지 않습니다. 먼저 자신의 예측과 관찰을 기록한 뒤 선택해서 엽니다.
빈 기록 칸은 생각을 쓰는 공간이지 실행을 막는 TODO가 아닙니다.

| 노트북 | 반드시 할 실험 | 결과 질문 / 체크포인트 |
|---|---|---|
| 00 | 같은 사규 질문에 지침만 변경 | 문서를 안 줬는데 맞힌 숫자를 믿을 수 있는가? 첫 응답/사용량 |
| 01 | 같은 날씨 질문, tool_choice auto → none | 요청과 실제 함수 실행은 어느 줄에서 갈리는가? 실행 횟수 |
| 02 | 같은 후속 질문, 세션 유지 → 교체 | Framework가 대신 한 것과 세션이 보존한 것은? 실제 함수 로그 |
| 03 | 로컬 청크 크기 100 → 300, 임베딩 문장 쌍 비교 | 금액과 적용 조건이 같이 남는가? 본인 업로드 수/실제 검색 |
| 04 | keyword/vector/hybrid 비교, 문서 전달 → 미전달 | 검색 실패와 생성 실패는 다른가? 원문과 주장/인용 일치 |
| 05 | 대화 상태 비교, 앱의 세 학습 모드 비교 | 누가 검색/외부 호출을 정했는가? 앱/실행 기록/초기화 |
| 06 | 기본 평가 후 자신의 사례 하나 추가 | 자동 통과와 실제 정답이 다른 경우는? 평가표/다음 조치 |

## 반드시 구분할 다섯 가지

1. **LLM:** 주어진 입력을 바탕으로 텍스트/도구 요청을 생성합니다. 최신 사실·사규 확인과 같지 않습니다.
2. **함수 실행:** Python이 허용된 함수/API를 실제 호출합니다. `function_call`은 실행이 아니라 요청입니다.
3. **Agent loop:** 모델 요청 → 함수 실행 → 결과 반환을 반복하며 상태·종료·제한을 관리합니다. 무제한 자율성이나 쓰기 권한을 뜻하지 않습니다.
4. **Search:** 문서 조각을 찾습니다. keyword는 단어 일치, vector는 의미 유사성, hybrid는 결합입니다. 점수 절댓값을 방식 간 직접 비교하지 않습니다.
5. **RAG:** 검색 근거를 모델 입력에 넣어 답변을 만듭니다. 인덱싱은 파인튜닝이 아니고, 인용이 있다고 정확성이 보장되지 않습니다.

앱의 **학습 모드** 명칭은 `plain LLM` / `RAG` / `Agent`, 검색 모드는 `keyword` / `vector` / `hybrid`입니다.
plain LLM은 모델만, RAG는 코드가 검색을 고정 실행, Agent는 도구 요청/실행 루프를 사용합니다.
Agent가 검색 도구를 쓰면 RAG 성격도 가집니다. Agent와 RAG는 상호 배타적인 기술 분류가 아닙니다.

## 앱 실행과 수료 조건

[수강생 안내](student.md)의 Codespaces 경로를 우선 사용합니다.

```bash
uv run python scripts/workshop.py doctor
uv run python scripts/workshop.py start
```

Codespaces Ports의 8501을 **Private**으로 열거나, 로컬 브라우저의 `http://localhost:8501`로 접속합니다.
App Service 배포는 필수가 아니며 수업 시간에 리소스 배포를 추가하지 않습니다.

수료 확인은 암기 시험 대신 다음 시연으로 합니다.
- 같은 사규 질문을 세 학습 모드에서 비교하고 **근거와 실제 호출**을 설명한다.
- 한빛테크 원문과 답변의 금액·통화·세금 조건을 대조한다.
- 모르는 규정/지원하지 않는 행동에 대해 추측이나 가짜 완료를 구분한다.
- 평가 사례 하나에 기대 행동·금지 행동·실제 결과·개선안을 기록한다.

## 초보자 속도 조절과 장애 대응

- 10명은 5개 짝으로 예측을 공유하되 실행은 각자 키/인덱스로 합니다. 한 명이 조작하고 다른 한 명은 근거를 읽은 뒤 역할을 바꿉니다.
- 환경 구축/모델·Search·APIM 준비는 수업 **전** 강사 책임입니다. 학생에게 Azure 관리 권한을 주지 않습니다.
- 401/403이나 설치 문제로 5분 이상 막히면 강사와 해결하고, 그동안 짝의 화면을 관찰해 기록합니다. 이를 본인의 라이브 성공으로 표시하지 않습니다.
- 시간이 밀리면 환율 도구 추가, 두 번째 청크 겹침 실험, 추가 평가 사례 수를 줄입니다. 필수 모드 비교/원문 검증/휴식은 유지합니다.
- 429에는 반복 클릭을 멈추고 순차 재시도합니다. 03 업로드는 5명씩 두 그룹으로 시작해 동시 부하를 줄입니다.
- 네트워크 장애 때는 로컬 청킹/원문 검토/예상 흐름 표시로 학습을 이어가되, 가짜 API 결과를 실제 실행처럼 제시하지 않습니다. 미검증 항목을 남깁니다.
- 공유 `/openai`는 변경하지 않습니다. 개인 키와 인덱스 경계는 서버 APIM이 강제하며 학생 `.env` 값 변경이 권한을 만들지 않습니다.

## 선택 확장: 수업 밖에서

작성 Agent → 검토 Agent 같은 멀티 에이전트, 실제 기업 문서 수집, 배포 자동화는 필수 과정에 넣지 않습니다.
먼저 단일 Agent의 도구·근거·비용·지연을 측정하고 추가 복잡성의 이득을 검증합니다.
호스팅 Codespaces 실행 성공은 실제 수업 환경에서 별도로 확인해야 하며 오프라인 검사 통과와 같지 않습니다.
