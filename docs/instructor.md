# 강사 운영 가이드 · 6시간 AI 이해 중심 워크숍

## 운영 원칙과 수료 기준

[360분 시간표](curriculum.md)를 기준으로 **수업 330분 + 휴식 30분**을 운영합니다. 대상은 초보자 10명이며, 최종 결과는 **Codespaces 우선 / 로컬 대안의 실행 가능한 Streamlit 앱**입니다. App Service 배포·공개 웹서비스 구축은 필수가 아닙니다.

- 시나리오는 가상 한빛테크 도쿄 출장으로 고정합니다. 숙박 규정/승인 절차 → 참고 환율 → 현재 날씨를 연결하되 예약·결제·실제 승인은 하지 않습니다.
- 학생은 개인 APIM 키와 본인 인덱스만 사용합니다. 공유 `/openai` API, 공유 모델의 기존 경로/정책은 변경하지 않습니다.
- 예측 → 실행 → 관찰 → 변경을 반복합니다. 강사가 정답을 먼저 보여주지 말고 “어떤 근거/함수가 필요할까?”를 먼저 묻습니다.
- 코드는 기본값으로 실행 가능한 발판입니다. 학생은 질문/지침/설정/평가 사례를 수정합니다. 접힌 **참고 풀이**는 예측/관찰 뒤 선택해서 열게 합니다.
- 통과 증거는 예쁜 답변이 아니라 **함수 로그, 검색 원문, 주장/인용 일치, 비교표, 추가 평가 사례**입니다.
- API 실패/미실행을 가짜 데이터로 대체하지 않습니다. 라이브 실행, 로컬 검사, 호스팅 Codespaces 점검은 별도 항목으로 기록합니다.

### 사전 준비: 수업 시간에 설치 문제를 떠넘기지 않기

수업 전날까지 아래를 확인하고, 수업 시작 전 짧게 재확인합니다.

- Codespaces 생성 권한/조직 정책/사용료, Dev Container 부팅, `.venv` 커널, 8501 Private 포트에서 앱 열기. **실제 호스팅 환경에서 확인한 경우에만 성공으로 기록**합니다.
- Codespaces가 불가능한 학생의 로컬 VS Code + Python 3.11 이상 + uv 경로. 두 경로 모두 같은 `doctor`/`start` 명령을 사용합니다.
- 학생 10명의 개인 파일 배정표와 각자 인덱스. 강사 파일을 학생에게 임시 공용으로 주지 않습니다.
- 강사 인덱스에서 00~06 라이브 실행, 모델/외부 API/검색 출처 확인. 수업 시작 전 학생 인덱스의 실제 상태도 확인하여 예상보다 많은 옛 청크가 없는지 점검합니다.
- 수업에서는 03 업로드를 5명씩 두 그룹으로 시작합니다. 불필요한 Run All 반복을 피하고 오류가 나면 한 번에 한 원인만 확인합니다.

## 1. 수업 전 확인

- 기존 Foundry 계정에 `gpt-5.6-terra` 배포가 준비되어 있어야 합니다.
- 기존 APIM의 system-assigned managed identity와 Foundry 계정 범위의 **Cognitive Services OpenAI User** 역할을 확인합니다. 스크립트는 공유 Foundry 역할을 임의로 확대하지 않습니다.
- 강사 Azure CLI 로그인(`az login`)과 대상 구독의 리소스 생성·좁은 범위 역할 할당·APIM 관리 권한이 필요합니다. 학생은 Azure 계정이 필요 없습니다.
- 조직의 공용 HTTPS 엔드포인트, 지역, GlobalStandard 모델 사용 정책을 확인합니다. 기본 자료는 공개 가능한 허구 문서뿐입니다.
- `uv sync --frozen`, 오프라인 테스트, 비용/수업 종료 후 삭제 계획을 확인합니다.

## 2. 구성

| 대상 | 구성 |
|---|---|
| 공유 Foundry | 기존 LLM 배포 유지, `text-embedding-3-small` 추가 배포 |
| 임베딩 | 1536차원, 이 계정에서 지원 확인된 GlobalStandard, capacity 30 |
| 전용 RG | `rg-agent-rag-workshop`, 한국 중부 |
| Search | Basic, replica 1 / partition 1, 로컬 키 인증 비활성 |
| 기존 APIM | 새 전용 `agent-rag-workshop` API, 경로 `/agent-rag`만 추가 |
| 개인 접근 | student01~student10 + instructor, API-scoped subscription 11개 |
| 실행 환경 | Codespaces 우선, 로컬 VS Code/Dev Container 대안; Notebook와 Streamlit 실행 |

기본 단일 replica 구성은 교육용이며 고가용성 SLA 목적이 아닙니다. 별도 Foundry 프로젝트나 호스팅 에이전트 리소스, App Service, Storage 리소스는 만들지 않습니다.

## 3. 읽기 전용 사전 점검 → 명시적 생성

다음은 Bash 예시입니다. `<...>`에 실제 환경 값을 넣습니다. 공유 리소스 정보와 구독 ID는 배포 담당자가 관리하며 public repo에 키를 넣지 않습니다.

```bash
az login
uv run python infra/provision.py \
  --subscription '<구독 ID>' \
  --foundry-rg '<기존 Foundry RG>' --foundry-name '<기존 Foundry 계정>' \
  --apim-rg '<기존 APIM RG>' --apim-name '<기존 APIM 이름>' \
  --embedding-sku GlobalStandard --dry-run
```

사전 점검에 성공하면 동일 명령의 `--dry-run`을 **`--apply`**로 바꿉니다. 새 서비스의 provisioning에는 시간이 걸릴 수 있습니다. 실패 시 새 리소스를 무작정 더 만들지 말고 `.local/provision-manifest.json`을 유지한 채 원인을 확인하고 같은 명령을 재실행합니다.

스크립트는 변경 전 manifest에 대상을 기록합니다. **manifest는 재실행·안전한 삭제에 필요하므로 비공개 백업**하세요. 같은 이름의 타 작업 리소스를 자동 인수하거나 기존 키를 임의 회전하지 않습니다. 기존 공유 API 정책은 변경하지 않습니다.

## 4. 개인 키 배포

생성/읽기 검증 후 `.local/attendees/`에 다음 파일이 생깁니다.

- `student01.env` … `student10.env`: 학생에게 **각자 본인 파일 하나만** 개인 채널로 전달
- `instructor.env`: 강사 전용, 학생에게 배포하지 않음

학생은 받은 파일을 저장소 루트의 `.env`로 저장합니다. 이 파일을 공개 채팅·GitHub·전체 수강생에게 공유하지 마세요. 강사용 파일 권한은 로컬에서 0600으로 설정합니다.

## 5. 수업 전 실제 검증

```bash
# 강사 파일을 root .env로 복사 — 비공개
cp .local/attendees/instructor.env .env
# Windows PowerShell: Copy-Item .local/attendees/instructor.env .env

uv run python scripts/workshop.py doctor
uv run python scripts/run_notebooks.py --check
# 아래부터는 실제 API 요청/비용 또는 인덱스 쓰기가 있습니다. 사전 승인된 범위에서만 실행합니다.
uv run python scripts/workshop.py doctor --live
uv run python scripts/run_notebooks.py --execute
uv run python scripts/live_security_check.py
uv run python scripts/workshop.py start
```

- 노트북은 별도 커널에서 순서대로 실행합니다. 03이 실제 인덱스를 생성/업로드합니다.
- 10명 동시 요청 검사는 학생별 개인 키를 사용합니다. 이는 **작은 실측 smoke test**이지 수업 내내 공유 모델 용량을 보장하는 부하 인증은 아닙니다.
- 다른 인덱스·서비스 관리·다른 API·이전 서버 응답 접근은 거부되어야 합니다.
- 성공 코드만으로 완료라고 판단하지 말고 문서 개수, 검색 결과, 출처, 실제 도구 호출까지 확인합니다.
- `.local/notebook-runs/`와 `.local/security-check.json`은 비공개입니다. public 원본은 출력 없는 상태를 유지합니다.

## 6. 수업 중 코칭과 판정

| 노트북 | 먼저 물을 질문 | 반드시 볼 증거 | 막히면 |
|---|---|---|---|
| 00 | 문서를 안 줬는데 이 금액을 믿을까? | 입력/출력, 지침 변경 전후 | 커널/개인 설정부터 확인 |
| 01 | 요청만 있었나, 정말 실행했나? | auto/none 실행 횟수, call_id 연결 | 단일 날씨 질문으로 축소 |
| 02 | 반복 코드를 누가 대신했나? | 함수 로그, 새 세션의 후속 질문 | 도구 추가 연습은 선택으로 미룸 |
| 03 | 금액과 조건이 같은 청크에 남나? | 로컬 청크 비교, 업로드 수/검색 읽기 | 청킹은 로컬로 진행, 업로드는 개별 지원 |
| 04 | 검색이 틀렸나, 답변 생성이 틀렸나? | 순위/원문, 문서 전달 유무 비교 | 검색어를 원문 어휘로 좁힘 |
| 05 | 같은 질문인데 정보 경로가 어떻게 다른가? | 실제 앱과 모드별 실행/출처 | 8501/Private, 인덱스 완료 여부 확인 |
| 06 | 자동 통과면 정말 맞나? | 금액/조건/금지 행동의 사람 검토 | 문구 오탐과 실제 실패를 분리 |

**학습 모드**는 `plain LLM` / `RAG` / `Agent`, 검색 모드는 `keyword` / `vector` / `hybrid`로 통일합니다.
plain LLM은 검색/외부 함수 없이 모델만 사용하고, RAG는 코드가 검색을 고정 실행하며, Agent는 모델의 도구 선택과 함수 실행 루프를 관리합니다.
Agent가 검색을 쓰면 RAG를 포함할 수도 있습니다. “더 복잡한 모드가 언제나 더 좋은 답”이라고 설명하지 않습니다.

### 초보자 진행을 지키는 방법

- 5개 짝에서 조작자/관찰자를 교대합니다. 키/인덱스는 끝까지 개인별로 유지합니다.
- 설치/401/403이 5분 넘으면 개별 지원하고 그동안 짝 화면을 관찰하게 합니다. 미실행 학생은 미검증으로 기록합니다.
- 시간이 부족하면 선택 도구 추가, 두 번째 파라미터 실험, 추가 평가 사례 수부터 줄입니다. 최종 앱 모드 비교와 원문 검증, 휴식은 생략하지 않습니다.
- 03의 로컬 `small_chunks` 실험은 업로드하지 않습니다. 기본 `chunks`만 본인 인덱스에 넣어 오래된 실험 청크와 섞이지 않도록 합니다.
- 429에는 반복 클릭을 멈추고 Retry-After/할당량을 확인합니다. 학생에게 키를 교체하거나 공용 경로로 우회하도록 안내하지 않습니다.
- 외부 API가 차단되면 실패 상태를 공개하고 원문/코드 흐름으로 수업을 이어갑니다. 사전 화면을 쓰면 실제 현재 실행이 아닌 녹화/기록임을 명시합니다.

- [ ] 같은 사규 질문을 세 학습 모드로 실행하고 모드 변경 시 새 대화로 초기화했다.

- [ ] Agent 후속 환산에서 `convert_currency`, 날씨 질문에서 `get_weather`의 실제 기록과 기준일/시각을 보았다.
- [ ] 모르는 규정/없는 예약 기능에서 추측·가짜 완료를 구분했다.

최종 설명 질문: **LLM / 함수 실행 / Agent loop / Search / RAG** 각각의 역할은 무엇인가? 앱 화면에서 증거를 가리킬 수 있는가?
06의 자동 검사에는 문자열/인용 ID 조건이 있어 오탐/미탐이 가능합니다. 통과 수만 발표하지 말고 사람이 확인한 원문/금지 행동과 실패 원인을 함께 공유합니다. 06은 비밀 노출 징후 외의 평가 실패를 기록표로 남기므로, 노트북 실행 완료만으로 평가 통과라고 보고하지 않습니다.

## 7. 비용과 할당량

한국 중부 Azure Retail Prices API 확인값(2026-09-27): Search Basic **US$0.101/시간**. 6시간 수업만 계산하면 US$0.606입니다. 실제로는 사전 준비·유휴 시간도 과금됩니다. 이 금액은 기록된 단가를 이용한 예시이지 현재 가격 재조회나 총수업비 견적이 아닙니다. Search 1 unit 기준이며 세금/계약 할인·모델/임베딩·APIM은 제외입니다.

**유휴 상태여도 Search 비용이 발생하며 삭제해야 멈춥니다.** 무료 정지 버튼이나 예산 자동 차단을 가정하지 마세요. 과금 알림/조직 budget은 별도로 설정하며 budget은 일반적으로 경고이지 자동 정지가 아닙니다. 이 저장소는 구독 전체의 예산 정책을 수정하지 않습니다.

개인별 APIM 요청 제한과 모델 입력/출력 제한이 있습니다. 기존 공유 모델의 다른 트래픽도 있으므로 수업 전 실제 10명 테스트를 다시 수행하세요. 429가 발생하면 반복 요청을 멈추고 Retry-After/할당량을 확인합니다.

## 8. 수업 후 폐기

먼저 삭제 계획을 확인합니다. **다음 명령은 기본적으로 dry-run**입니다.

```bash
uv run python infra/teardown.py --confirm rg-agent-rag-workshop --dry-run
# 대상 확인 후에만 실행
uv run python infra/teardown.py --confirm rg-agent-rag-workshop --apply
```

manifest 소유의 개인 subscriptions, 전용 API, 추가 임베딩 배포, Search 역할 할당, 전용 RG만 삭제합니다. 공유 Foundry/APIM 부모는 삭제하지 않습니다. 전용 RG에 알 수 없는 다른 리소스가 있으면 group 삭제를 거부합니다. 로컬 env 파일은 자동으로 지워지지 않지만 원격 subscription 삭제 후 사용할 수 없게 됩니다.

> 실제 삭제는 수업이 끝난 뒤 수행하세요. 저장소 제작 시에는 학생 실습을 위해 리소스를 남겨둡니다.
